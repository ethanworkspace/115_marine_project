# Phase 19 Actual Edge Device Evaluation — prepared, not executed

## Purpose and limits

Evaluate hardware feasibility and quality/reliability tradeoffs on an actual,
explicitly named edge target. The Windows RTX 4060 evaluation host is not presumed
to be that target. No hardware benchmark is run in Phase 18, no model winner is
selected, and no production migration is authorized by this document.

The benchmark is AI-generated Corpus-Grounded Silver. Silver-reference metrics
are not human expert correctness. All references were generated by Gemma 2 9B;
reference_alignment_bias_possible must remain true. A Qwen Generator cannot use
the identical Qwen Primary Judge for primary quality conclusions.

## Freeze before the first device result

- Fixed test file: `reports/evaluation/validity/phase18/edge_benchmark_subset_v1.jsonl`.
  It contains 60 question IDs: 20 Direct, 20 Paraphrase, 20 Contextual. Species,
  categories and frozen E4 Top-5 context character-length bands are covered where
  available; no fabricated milkfish cases. Selection policy and SHA-256 are in
  the Phase 18 manifest. Do not change questions after device results appear.
- Character bands are deterministic corpus tertiles, not tokenizer-independent
  token capacity estimates. Record actual input token counts separately.
- Freeze target manufacturer/model, CPU, GPU/accelerator, physical and unified
  memory, OS/build, drivers, firmware, power mode, thermal/cooling configuration,
  runtime version and measurement tools. Record both idle and loaded conditions.
- Copy or resolve the exact selected model artifact: model/tag, digest,
  quantization, architecture, parameters, runtime format, file checksums and
  acquisition provenance. A quantization/artifact change is a separate experiment;
  do not hide it under an unchanged model name.
- Freeze candidate roster and supported runtime settings before execution. The
  Phase 18 shortlist is provisional; Gemma is the first hardware feasibility
  candidate, Qwen is a performance exploratory candidate with quality unresolved,
  and DeepSeek models are optional lower-priority execution diagnostics.

## Common generation contract

Reuse generation_v2 and its original schema, Protocol v2.2, temperature 0,
top_p 1, seed 15015 where supported, maximum output 1024, maximum attempts 2.
Use exactly the frozen E4 Top-5 chunks, context IDs/order/text and question.
Never use reference answers, required-evidence labels or scores in the prompt.
No per-model prompt/parser, output budget, evidence shortening or semantic repair.
If native context capacity cannot hold input plus output reservation, mark
context_capacity_failure; do not silently truncate or reduce Top-5.
Unsupported runtime features stay explicit, not simulated.

## Measurements and run order

Predeclare a deterministic roster order and use rotating blocks across models
for three full passes of the same 60 questions. Retain every attempt. First-pass
and final reliability are distinct; no best-run selection. Document warmup calls
separately and do not count them as benchmark answers. Use one edge device and
the same power mode for within-device latency comparisons. Different devices get
separate results, never an unlabeled pooled speed comparison.

| Metric | Definition / required scope |
|---|---|
| Model load | Runtime reported load duration and wall-clock readiness; separate cold/warm, OS cache and prior resident state |
| TTFT | Request to first final-answer content token; also record native thinking latency separately if exposed |
| TPS | Output token count / runtime decode duration; specify whether native thinking tokens are included |
| Total latency | Full execution protocol including technical retry; retain first/final-attempt times |
| RAM | Sample interval, process family or whole-device scope, peak and baseline; shared pages must not be claimed unique |
| VRAM/unified memory | Process allocation versus device-wide use; unified memory is not simply added to RAM |
| Power | Meter/sensor, sample interval, idle baseline, loaded mean/peak and energy per request where measurable |
| Thermal | Sensor identity, ambient condition, temperatures and throttle flags where measurable |
| Context capacity | Prompt tokens, context limit, output reservation, remaining margin and input/output truncation |
| Reliability | First/final JSON and schema validity, retries, raw preservation, errors, citation parse/provenance |
| Quality | Same fixed subset: faithfulness/relevance, citation recall, human/AI support status, abstention; Silver correctness/F1 separate |

Record mean, median, p95, sample count and missing measurements. Unavailable power,
temperature or process-level memory remains null with a reason. Record CPU/GPU
offload and accelerator allocation; do not estimate missing values. Clearly
separate generation-only latency from retrieval/reranker latency: Phase 19 reuses
frozen context and cannot pretend retrieval was timed live.

## Validity and release gates

Retain model/condition/question pairing, raw hashes, context checksums and all
technical failures. Use 10,000 paired bootstrap iterations, seed 19019, for
predeclared quality or latency differences on matched valid observations; this
only describes the fixed Silver sample. Reliability always retains the full
60-question denominator. Human judgments remain separate from AI audits.

Do not create an arbitrary weighted quality-speed score. Report quality,
reliability, latency, memory and energy axes, with descriptive Pareto frontiers
only where measurements are comparable. An edge feasibility pass is not a claim
of authoritative answer correctness or permission to migrate production.

Before Phase 19 can execute, the user must supply/select the actual edge target,
available memory/power constraints and runtime. Independent Judge and human
claim-citation work remain required for stronger final model-quality conclusions.
